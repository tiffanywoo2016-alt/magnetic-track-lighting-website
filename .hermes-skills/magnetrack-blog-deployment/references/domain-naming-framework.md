# Domain Naming Decision Framework (MAGNETRACK / B2B Lighting Brand)

Captured from session 2026-06-13 where user evaluated three domain names for the MAGNETRACK website.

## The Decision Path

```
proposed: lumitraclighting.com  →  reviewed: tracklinear.com  →  final: tracklinearlighting.com
```

## User Preferences (Derived from 3 Rounds of Feedback)

### What User Values
| Factor | Weight | Evidence |
|--------|--------|----------|
| **Availability** | 🟢 Highest | User asks about specific .com names — check availability first, always |
| **Self-explanatory** | 🟢 High | All three candidates contain product keywords (trac/linear/lighting) |
| **.com TLD** | 🟢 Non-negotiable | User only asks about .com — never propose .io/.net/.co for this project |
| **Brand+Product combo** | 🟢 Preferred | "lumitrac" = brand name only (rejected conceptually) vs "tracklinear" = product+product, "tracklinearlighting" = product+product+category |

### What User Does NOT Value (from this session)
- **Brevity alone** — `tracklinear.com` (13 chars) was preferred over `lumitraclighting.com` (19 chars), but user ultimately chose `tracklinearlighting.com` (23 chars) which is longer. Brevity is not the deciding factor.
- **Pure brand names** — `lumitraclighting` where "lumitrac" is invented was less favored than descriptive compound names.

## Recommended Evaluation Order for Future Proposals

When user asks "X.com 可以吗" or "帮我想个域名":

```
Step 1: Check availability with `host <name>.com`
Step 2: Compare candidates on 4 dimensions:
  - Length (chars) — user will accept up to 23 chars
  - Explainability  — does it describe what the brand does?
  - SEO value       — does it contain product keywords?
  - Memorability    — will someone type it correctly after hearing it?
Step 3: Give a recommendation with rationale, but let user decide
Step 4: If user keeps asking about alternatives (3+ rounds), they may have already decided — just provide the availability check
```
